# PLC POS — แผนผลิตภัณฑ์ (PM)

> อัปเดตล่าสุด: 2026-10-26 · คู่กับ [`database-design.md`](./database-design.md)
> ไฟล์นี้กำหนดว่า**จะทำอะไร ทำอะไรก่อน และเมื่อไรถือว่าเสร็จ** ส่วนรายละเอียดตารางอยู่ใน `database-design.md`

## 1. เป้าหมายและผู้ใช้

**เป้าหมาย:** ระบบ POS สำหรับร้านขายอุปกรณ์ POS และไอทีหนึ่งสาขา ที่ทำได้ตั้งแต่ขายหน้าร้าน (หลายสกุลเงิน + VAT) สต็อกแบบมี serial ลูกหนี้ จนถึงงานซ่อมและรับประกัน โดยเจ้าของร้านดูตัวเลขที่สำคัญได้ทุกวัน

| ผู้ใช้ | งานหลัก |
|---|---|
| เจ้าของร้าน / Admin | ตั้งค่า, ราคา, ผู้ใช้, ดูรายงานและกำไร |
| ผู้จัดการ | รับสินค้า, ปรับสต็อก, อนุมัติ void/แก้ราคา, ติดตามหนี้ |
| แคชเชียร์ | เปิด/ปิดกะ, ขาย, รับชำระหนี้, รับเครื่องซ่อม |
| ช่างเทคนิค | อัปเดตสถานะซ่อม, ใส่อะไหล่/ค่าแรง |
| พนักงานทั่วไป (Viewer) | ค้นหาหรือสแกนดูสินค้า สต็อก และตำแหน่งชั้นวาง |

## 2. ข้อเสนอปรับปรุงจาก PM

สิ่งที่ไม่อยู่ในรายการฟีเจอร์เดิม แต่ร้านประเภทนี้จำเป็นต้องมี

### P0 — ต้องมีก่อนเปิดใช้จริง
| # | ข้อเสนอ | เหตุผล | สถานะในการออกแบบ |
|---|---|---|---|
| 1 | **PIN แคชเชียร์ + PIN ผู้จัดการอนุมัติ** (void, แก้ราคา, ส่วนลดเกินเกณฑ์) ที่เครื่องขาย | ไม่ต้องล็อกเอาต์แล้วล็อกอินใหม่ทุกครั้ง ร้านจะใช้สิทธิ์ได้จริง | ✅ เพิ่ม `User.pinHash` แล้ว |
| 2 | **รายงานปิดกะ (Z-report)** แยกเงินตามสกุลและประเภทชำระ แสดงเงินขาด/เกิน | ป้องกันเงินหาย เป็นเครื่องมือที่เจ้าของร้านใช้ทุกวัน | ✅ มีใน `Shift.expectedCash` |
| 3 | **ใบกำกับภาษี (Tax invoice)** แยกเลขสำหรับลูกค้าธุรกิจ พิมพ์ A4 พร้อมเลขผู้เสียภาษี | VAT 12% กับลูกค้า B2B ต้องใช้ | ✅ ตาราง `TaxInvoice` + รูปแบบใน `database-design.md` หัวข้อ 11 |
| 4 | **สแกน serial ต่อเนื่องตอนรับสินค้า** (ยิงทีละหลายสิบเครื่อง หรือ import CSV) | รับเครื่อง POS ครั้งละ 20–50 เครื่อง การพิมพ์ทีละตัวช้าและผิดง่าย | ฟีเจอร์ API/UI |
| 5 | **ค้นหาประกันจาก serial** สแกนแล้วเห็นว่าขายเมื่อไร ให้ใคร บิลไหน ประกันเหลือกี่วัน | ลูกค้ามาเคลมบ่อยที่สุด ต้องตอบได้ในไม่กี่วินาที | ✅ มีใน `SerialNumber` |
| 6 | **สำรองข้อมูลอัตโนมัติทุกวัน** + ทดสอบกู้คืน | ข้อมูลขายและหนี้หายไม่ได้ | งาน DevOps |
| 7 | **หลายเครื่องขาย + พิมพ์ ESC/POS ตรง + เปิดลิ้นชักอัตโนมัติ** | ร้านมีหลายเคาน์เตอร์ (D3, D4) | ✅ ตาราง `Register` + print bridge (`database-design.md` หัวข้อ 10) |

### P1 — ทำต่อเนื่องหลังเปิดใช้
| # | ข้อเสนอ | เหตุผล | สถานะ |
|---|---|---|---|
| 8 | **ประกันจากผู้จำหน่าย + ส่งเคลมผู้จำหน่าย (RMA)** | ร้านต้องเคลมต่อไปยังตัวแทน จึงต้องรู้ว่าเครื่องไหนยังอยู่ในประกันผู้จำหน่าย | ✅ เพิ่ม `SerialNumber.supplierWarrantyEndsAt`, `ServiceTicket.supplierId` แล้ว |
| 9 | **Dashboard หน้าแรก:** ยอดขายวันนี้, กำไร, สินค้าใกล้หมด, หนี้ถึงกำหนด, งานซ่อมที่เสร็จรอส่ง | เจ้าของเปิดดูได้ใน 5 วินาที | query |
| 10 | **ตรวจนับสต็อก (Stock count)** สแกนนับแล้วสร้างเอกสาร ADJUST ให้อัตโนมัติ | ร้านที่มี serial ควรนับทุกเดือน | ใช้ `StockDocument` ADJUST |
| 11 | **แจ้งเตือน:** หนี้เลยกำหนด, ประกันลูกค้าใกล้หมด (โอกาสขายต่อประกัน), ล็อตใกล้หมดอายุ | เพิ่มรายได้และลดหนี้เสีย | query + UI |
| 12 | **ประวัติลูกค้า:** ซื้ออะไร serial อะไร หนี้ และงานซ่อม | ช่วยงานบริการและการขายซ้ำ | query |
| 13 | **ส่งใบเสนอราคา/บิลเป็น PDF** (แชร์ผ่าน WhatsApp/LINE) | ลูกค้า B2B ในลาวสื่อสารผ่านแชต | ฟีเจอร์ API |

### P2 — อนาคต
นัดหมายงานติดตั้งนอกสถานที่, สะสมแต้ม, หลายสาขา, e-invoice/เชื่อมระบบภาษี, แคตตาล็อกออนไลน์

## 3. ขอบเขต MVP (เฟส 1) และเกณฑ์ "เสร็จ"

| โมดูล | เกณฑ์ยอมรับ (Acceptance) |
|---|---|
| ล็อกอิน + สิทธิ์ | ล็อกอินด้วย username/password หรือ PIN · เมนูและ API ถูกจำกัดตามสิทธิ์ของกลุ่ม · Viewer ไม่เห็นต้นทุน |
| ตั้งค่า | แก้ข้อมูลร้าน/โลโก้, VAT (12%), อัตราแลกเปลี่ยน, เปิด/ปิดประเภทชำระเงินได้ |
| สินค้า | เพิ่ม/แก้สินค้าพร้อมรูป, specs, ราคาปลีก/ส่ง, ราคาเป็น USD แล้วได้ราคากีบที่ปัดหลักพัน |
| รับสินค้า | สร้างใบรับสินค้า สแกน serial ต่อเนื่อง ต้นทุนเฉลี่ยอัปเดตถูกต้อง |
| ขาย | สแกนแล้วเข้าตะกร้าเร็วกว่า 300ms · บังคับ serial · ส่วนลดรายการ/ท้ายบิล · VAT ถูกต้อง · จ่ายหลายสกุล/หลายประเภท · ขายเชื่อ · พักบิล · พิมพ์ 58/80mm/A4 |
| Void | ต้องใช้ PIN ผู้จัดการ · สต็อกและ serial คืนครบ · มีบันทึกใน AuditLog |
| ลูกหนี้ | ดูหนี้แยกตามลูกค้า · รับชำระบางส่วนได้ · สถานะบิลอัปเดต |
| กะ | เปิดกะด้วยเงินตั้งต้นแยกสกุล · ปิดกะแสดง Z-report และส่วนต่าง |
| รายงาน | ยอดขายรายวัน/ช่วงวันที่, สินค้าขายดี, กำไร, บิลที่ void, ลูกหนี้ |
| คุณภาพ | unit test ครอบคลุมการคำนวณเงิน/VAT/สต็อก · e2e สำหรับขั้นตอนขาย → void → ชำระหนี้ |

## 5. ข้อกำหนดที่ไม่ใช่ฟังก์ชัน

- **ภาษา:** ลาว (หลัก), ไทย, อังกฤษ · ใบเสร็จพิมพ์ตามภาษาที่เลือก
- **เวลา:** `Asia/Vientiane` · รายงาน "รายวัน" ตัดรอบตามเวลาท้องถิ่น
- **เงิน:** ห้ามใช้ float คำนวณยอด · LAK เป็นจำนวนเต็ม · snapshot อัตราแลกเปลี่ยน/VAT/ต้นทุนในทุกบิล
- **ความปลอดภัย:** argon2 สำหรับรหัสผ่านและ PIN · ล็อก PIN หลังผิด 5 ครั้ง · AuditLog สำหรับการกระทำที่อ่อนไหว
- **ประสิทธิภาพ:** ค้นหาหรือสแกนสินค้าตอบกลับเร็วกว่า 300ms · สินค้า 10,000 รายการ · บิล 100,000 ใบต่อปี
- **ความทนทาน:** backup รายวัน เก็บย้อนหลัง 30 วัน

## 7. ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| เน็ตในร้านล่ม (ระบบอยู่บน cloud) | ขายไม่ได้ | 4G router สำรอง · offline mode อยู่ใน backlog |
| print bridge ใช้ไม่ได้กับบางเครื่องพิมพ์ | พิมพ์ไม่ได้ | กลับไปพิมพ์ผ่าน browser · ทดสอบกับรุ่นที่ร้านขาย (Epson, Xprinter) ก่อน |
| ขอบเขตกว้าง (40 ตาราง) | ส่งมอบช้า | ล็อกขอบเขต MVP ตามข้อ 3 ส่วนที่เหลือเป็นเฟส 2–3 |
| สต็อก/serial ไม่ตรงความจริง | เสียความเชื่อมั่นในระบบ | ledger แบบ insert-only + ตรวจนับ + test ที่ครอบคลุม |
| อัตราแลกเปลี่ยนผันผวน | ขายขาดทุน | สินค้านำเข้าตั้งราคาเป็น USD + ปัดขึ้น + อัปเดตอัตราทุกวัน |
| พนักงานไม่ยอมใช้ | ระบบถูกทิ้ง | UI ภาษาลาว, ใช้สแกนเป็นหลัก, PIN, ทดลองใช้ (pilot) พร้อมอบรม |
